# 統合テスト式様書（Integration Test Specification）

## 1. テスト概要

### 1.1 テスト対象システム
**システム名**: 社会保险バックエンドサービス（Social Insurance Backend Service）  
**テスト対象API**: 社会保险金額照会API（`/socialInsuranceQuery`）  
**テスト種別**: 統合テスト（Integration Test）  
**テスト実施日**: -  
**テスト実施者**: -  
**バージョン**: 0.0.1

### 1.2 テスト環境
- **フレームワーク**: Spring Boot 4.0.0 (WebFlux)
- **データベース**: PostgreSQL 17.4 (Testcontainers)
- **テストツール**: JUnit 5, WebTestClient, AssertJ
- **Java バージョン**: 21
- **テストプロファイル**: `test`

### 1.3 テスト範囲
本テスト式様書は、社会保险金額照会APIの正常系および異常系統合テストを対象とする。  
統合テストでは、以下の要素を統合してテストする：
- HTTPリクエスト/レスポンス処理（Controller層）
- ビジネスロジック（Application層、Domain層）
- データベースアクセス（Repository層）
- 実際のPostgreSQLデータベースとの連携
- 例外処理（GlobalExceptionHandler）

### 1.4 統合テストの特徴
- `@SpringBootTest`により、完全なアプリケーションコンテキストをロード
- `RANDOM_PORT`により、実際のHTTPサーバーを起動
- `Testcontainers`により、実際のPostgreSQLデータベースを使用
- `@ActiveProfiles("test")`により、テスト用の設定を適用
- エンドツーエンドのフローをテスト（HTTPリクエスト → データベース → HTTPレスポンス）

## 3. テスト項目詳細

### 3.1 TC-001: アプリケーションコンテキストロード確認

#### 3.1.1 テスト目的
Spring Bootアプリケーションが正常に起動し、コンテキストが正しくロードされることを確認する。

#### 3.1.2 前提条件
- PostgreSQLデータベースコンテナが起動していること
- アプリケーションの設定ファイルが正しく配置されていること
- テストプロファイル（`test`）が有効であること

#### 3.1.3 テスト手順
1. Spring Bootアプリケーションを起動する
2. `@SpringBootTest`アノテーションにより、アプリケーションコンテキストをロードする
3. `@Testcontainers`により、PostgreSQLコンテナを自動起動する

#### 3.1.4 期待結果
- アプリケーションコンテキストが正常にロードされること
- PostgreSQLコンテナが正常に起動すること
- エラーが発生しないこと

#### 3.1.5 判定基準
- テストが正常に実行され、例外が発生しないこと
- すべてのBeanが正常に初期化されること

### 3.2 TC-002: 社会保险金額照会（40歳以上・月給55万円）

#### 3.2.1 テスト目的
40歳以上の従業員（月給55万円）に対する社会保险金額が正しく計算されることを確認する。  
特に、介護保険が適用されることを確認する。

#### 3.2.2 前提条件
- PostgreSQLデータベースコンテナが起動していること
- 保険料等級テーブルに必要なデータが登録されていること
- WebTestClientが正しく初期化されていること
- データベースマイグレーション（Flyway）が正常に実行されていること

#### 3.2.3 テストデータ
| 項目 | 値 |
|-----|-----|
| 月給（monthlySalary） | 550,000円 |
| 年齢（age） | 45歳 |

#### 3.2.4 テスト手順
1. HTTP GETリクエストを送信する
   - URL: `/socialInsuranceQuery?monthlySalary=550000&age=45`
   - メソッド: GET
2. レスポンスを取得する
3. レスポンスの各項目を検証する

#### 3.2.5 期待結果

##### 3.2.5.1 HTTPレスポンス
- **ステータスコード**: 200 OK
- **Content-Type**: `application/json`

##### 3.2.5.2 レスポンスボディ（従業員負担額）
| 項目 | 期待値 | 単位 |
|-----|--------|------|
| 健康保険料（介護なし） | 27,776.00 | 円 |
| 介護保険料 | 4,452.00 | 円 |
| 厚生年金保険料 | 51,240.00 | 円 |

##### 3.2.5.3 レスポンスボディ（事業主負担額）
| 項目 | 期待値 | 単位 |
|-----|--------|------|
| 健康保険料（介護なし） | 27,776.00 | 円 |
| 介護保険料 | 4,452.00 | 円 |
| 厚生年金保険料 | 51,240.00 | 円 |

##### 3.2.5.4 レスポンスJSON構造
```json
{
  "employeeCost": {
    "healthCostWithNoCare": 27776.00,
    "careCost": 4452.00,
    "pension": 51240.00
  },
  "employerCost": {
    "healthCostWithNoCare": 27776.00,
    "careCost": 4452.00,
    "pension": 51240.00
  }
}
```

#### 3.2.6 判定基準
- HTTPステータスコードが200 OKであること
- レスポンスボディの各項目が期待値と一致すること
- 従業員負担額と事業主負担額が一致すること（このケースでは同額）
- 介護保険料が0円ではないこと（40歳以上であるため）

#### 3.2.7 備考
- 40歳以上の従業員は介護保険の対象となるため、`careCost`が0円以外の値となる
- 金額は`BigDecimal`型で比較し、精度を保証する
- このテストは統合テストのため、実際のデータベースとの連携を検証している

### 3.4 TC-004: 社会保险金額照会（存在しない月給・異常系）

#### 3.4.1 テスト目的
保険料等級テーブルに存在しない月給を指定した場合、適切なエラーレスポンスが返されることを確認する。

#### 3.4.2 前提条件
- PostgreSQLデータベースコンテナが起動していること
- 保険料等級テーブルに必要なデータが登録されていること
- WebTestClientが正しく初期化されていること
- データベースマイグレーション（Flyway）が正常に実行されていること
- グローバル例外ハンドラー（GlobalExceptionHandler）が正しく設定されていること

#### 3.4.3 テストデータ
| 項目 | 値 |
|-----|-----|
| 月給（monthlySalary） | 1,050,000円（保険料等級テーブルに存在しない値） |
| 年齢（age） | 30歳 |

#### 3.4.4 テスト手順
1. HTTP GETリクエストを送信する
   - URL: `/socialInsuranceQuery?monthlySalary=1050000&age=30`
   - メソッド: GET
2. レスポンスを取得する
3. エラーレスポンスの内容を検証する

#### 3.4.5 期待結果

##### 3.4.5.1 HTTPレスポンス
- **ステータスコード**: 400 Bad Request
- **Content-Type**: `application/json` または `text/plain`

##### 3.4.5.2 エラーメッセージ
レスポンスボディに以下のメッセージが含まれること：
- `"未找到月薪 1050000 对应的保险费等级"` または類似のエラーメッセージ

##### 3.4.5.3 エラーレスポンス構造（例）
```json
{
  "timestamp": "2025-01-XX...",
  "status": 400,
  "error": "Bad Request",
  "message": "未找到月薪 1050000 对应的保险费等级",
  "path": "/socialInsuranceQuery"
}
```

または

```
未找到月薪 1050000 对应的保险费等级
```

#### 3.4.6 判定基準
- HTTPステータスコードが400 Bad Requestであること
- エラーメッセージが適切に返されること
- エラーメッセージに指定した月給（1050000）が含まれること
- グローバル例外ハンドラーが正しく動作していること

#### 3.4.7 備考
- このテストは異常系の統合テストである
- `IllegalArgumentException`が適切にキャッチされ、HTTPレスポンスに変換されることを確認する
- エラーメッセージの形式は、実装されている例外ハンドラーによって異なる場合がある

## 7. 参考情報

### 7.1 API仕様
- **エンドポイント**: `/socialInsuranceQuery`
- **HTTPメソッド**: GET
- **リクエストパラメータ**:
  - `monthlySalary` (Integer, 必須): 月給
  - `age` (Integer, 必須): 年齢
- **レスポンス形式**: JSON（正常系）、JSONまたはテキスト（異常系）

### 7.2 関連ドキュメント
- ソースコード: `src/test/java/jp/asatex/niuyuping/social_insurance_backend_service/SocialInsuranceBackendServiceApplicationTests.java`
- コントローラー: `src/main/java/jp/asatex/niuyuping/social_insurance_backend_service/controller/PremiumBracketController.java`

- 例外ハンドラー: `src/main/java/jp/asatex/niuyuping/social_insurance_backend_service/controller/GlobalExceptionHandler.java`

### 7.3 テストアノテーション
- `@Testcontainers`: Testcontainersの統合
- `@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)`: 完全なアプリケーションコンテキストのロードとHTTPサーバーの起動
- `@ActiveProfiles("test")`: テストプロファイルの有効化
- `@Container` + `@ServiceConnection`: PostgreSQLコンテナの自動起動と接続設定
